# Security Policy

## Supported versions

The latest release on `main` receives fixes. Older tags are not maintained.

| Version | Supported |
|---------|-----------|
| 1.x     | ✅        |

## Reporting a vulnerability

Please **do not open a public issue** for a security problem.

Use GitHub's private vulnerability reporting:

1. Go to the repository's **Security** tab.
2. Choose **Report a vulnerability**.
3. Describe the issue, the affected component, and a reproduction if you
   have one.

You should get an acknowledgement within a few days. If the report is
accepted, a fix and an advisory will be prepared, and you will be credited
unless you prefer otherwise.

## What is in scope

This application runs entirely as the logged-in user and makes no network
connections. Areas worth reviewing include:

* the installer and uninstaller (`install.sh`, `uninstall.sh`) and the
  files they write under `~/.local/share` and `~/.config`;
* the systemd **user** unit generated by the installer;
* SQLite handling in `database.py` (queries, migrations);
* parsing of `journalctl` and `last` output in `uptime.py`;
* the Tkinter UI's handling of local dates and text.

## Out of scope

* Anything requiring root: the project never asks for root except to
  install missing distro packages.
* Vulnerabilities in Parrot OS, Tkinter, matplotlib, or SQLite themselves —
  report those upstream.
* Findings that require an attacker to already control the user's account
  or local files.

## Design guarantees

The dashboard is offline by design. It does not contact any server, does
not collect telemetry, and does not read files outside `/proc`, journald,
wtmp, and its own data directory.
